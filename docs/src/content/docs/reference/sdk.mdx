Integrator packages:

- [`@sai-labs/guard`](https://www.npmjs.com/package/@sai-labs/guard) — TypeScript client for `protect()`
- [`@sai-labs/guard-mcp`](https://www.npmjs.com/package/@sai-labs/guard-mcp) — MCP server over that client

The v0.1 attestation gate remains [`@sai-labs/vap`](https://www.npmjs.com/package/@sai-labs/vap) / [`@sai-labs/vap-mcp`](https://www.npmjs.com/package/@sai-labs/vap-mcp). Wire hashes still use the `VAP/0.1/` domain prefix. See [from v0.1](/reference/migration/).

MCP is a transport. [MCP authorization](https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization) authenticates a client to a server. It does not approve a transaction.

[GitHub](https://github.com/SAI-Labs-Tech/vap)

## Installation

```bash
npm install @sai-labs/guard
```

```ts
import { SaiGuard } from "@sai-labs/guard";

const guard = new SaiGuard({
  apiKey: process.env.SAI_GUARD_API_KEY,
});

const result = await guard.protect({
  chain: "ethereum",
  intent,
  transaction,
});

if (result.verdict === "BLOCKED") {
  return;
}

// Signing stays in the wallet / calling application.
```

`POST /v1/protect` is not deployed on the current HTTP API. The SDK maps HTTP 404 to `PROTECT_UNAVAILABLE` instead of inventing a verdict. See [protocol status](/reference/status/).

## MCP

```bash
npx @sai-labs/guard-mcp
```

v0.1 tool: `guard_protect_transaction`. The MCP server does not sign or broadcast.

## Available: v0.1 runtime

```ts
import { VapRuntime } from "@sai-labs/vap";

const vap = new VapRuntime();
vap.registerMandate(mandate);
vap.authorizeIntent(intent, mandate.mandateId);
const prepared = vap.prepareAction(intent.intentId);
vap.submitProposal({ intentId: intent.intentId, prepared, executorId, expiresAt });
vap.submitAttestation({ intentId: intent.intentId, role: "semantic-verifier" });
vap.submitAttestation({ intentId: intent.intentId, role: "safety-verifier" });
const done = vap.executeApproved(intent.intentId);
```

The agent scope does not mint intents and does not hold execution credentials. `UNSUPPORTED_CAPABILITY` if the adapter cannot bind an exact payload.

## MCP tools (v0.1 gate)

| Tool | Caller |
| --- | --- |
| `vap.get_capabilities` | Authenticated client |
| `vap.prepare_action` / `vap.submit_proposal` | Agent |
| `vap.get_status` / `vap.get_receipt` | Tenant client |
| `vap.submit_attestation` | Verifier |
| `vap.execute_approved` | Executor; gate still runs |

Default `VAP_SCOPE=agent`. HTTP: `https://vap-api.saiwallet.ai`.
